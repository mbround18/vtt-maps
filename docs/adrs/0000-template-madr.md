## Template for Architecture Decision Records

This is a template based on [MADR 4.0.0](https://adr.github.io/madr/) for documenting architectural decisions.

## Context

Describe the issue or problem that motivates this decision or any context that drives the current state of affairs.

A concise statement of the decision itself using the Y-Statement format:

> In the context of [use case/feature], facing [concern/problem], we decided for [option] to achieve [desired quality], accepting [downside/trade-off], because [rationale].

## Notes

This template follows the MADR 4.0.0 specification from the ADR GitHub organization. It emphasizes the importance of documenting:

1. **Context**: What led to this decision?
2. **Decision**: What was decided and why (Y-Statement)?
3. **Considered Options**: What alternatives were evaluated?
4. **Consequences**: What are the outcomes?

Each decision should be self-contained and enable understanding the trade-offs made.
